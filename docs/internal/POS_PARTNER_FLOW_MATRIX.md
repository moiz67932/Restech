# POS partner flow matrix

| Flow                                                | Runtime verdict                                                                                                         | v1 contract verdict  | Remaining work                                              |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------------------------------------------------------- |
| Bill open/update/table move/cancel/close            | Full-snapshot versioned upsert exists; table mapping, totals, state, and version are validated                          | Supported            | Run partner UAT against deployed migration/build            |
| New bill on a previously used table                 | New external bill ID at version 1 is supported                                                                          | Supported            | Partner must prove ID non-reuse in UAT                      |
| Stable table/customer QR resolves current bill      | No route or repository query exists in current source                                                                   | Not supported        | Approve selection/privacy lifecycle, implement, and certify |
| Session-specific customer checkout                  | Session creation returns an opaque Restec-hosted URL; status is authoritative only after an event                       | Supported            | Deploy latest terminal-page guard                           |
| Digital payment to POS                              | Durable signed, versioned partner event with idempotent delivery exists                                                 | Supported            | Re-run fresh deployed scheduler-only certification          |
| Duplicate digital event                             | Inbox and outbox uniqueness prevent a second POS result                                                                 | Supported            | Database concurrency test must run in required CI           |
| Cash/physical terminal/wallet terminal/voucher      | Completed external-payment endpoint uses the domain client, validates balance/currency/state, is idempotent, and audits | Supported            | Apply credential migration and perform deployed UAT         |
| POS-originated pending/decline/cancel/void/reversal | No approved domain policy or endpoint                                                                                   | Rejected/unsupported | Product, finance, and compliance decision                   |
| POS-originated refund/partial refund                | No initiating endpoint                                                                                                  | Rejected/unsupported | Product, finance, and compliance decision                   |
| Authoritative digital refund notifications          | Existing event receiver projects refund state and sends a partner callback                                              | Receive-only         | End-to-end deployed refund UAT                              |
