# Current normal-payment lifecycle trace

This trace records the runtime observed at the Phase 4 baseline. “Reserved” includes ambiguous protected capacity.

| Flow                            | Authority and state transition                                                                                              | Capacity / bill / event / retry / scheduler                                                                                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Digital create                  | POS request -> Restec validation -> Phase 1 reserve -> private create -> attach as `requires_customer_action`               | Full requested amount is protected before the external call. Same-key retry returns the same session. One active digital session per bill.                                                     |
| Customer opens checkout         | Restec validates session and local checkout time, leases refresh, asks private service for a new capability, then redirects | Baseline bug: a locally due session was changed to `expired` by this browser GET. No canonical POS event was created.                                                                          |
| Processing                      | Signed event or private reconciliation read may move an active session to `processing`                                      | Reservation remains protected. Browser is not authority. Baseline reconciliation only applied non-terminal reads before local expiry.                                                          |
| Paid                            | Signed `payment.completed` event -> atomic session/reservation/bill/inbox/outbox commit                                     | Reservation becomes completed; private bill projection sets partial/full balance. Duplicate completion is logically deduplicated. Late paid may reacquire released capacity only if available. |
| Failed                          | Signed `payment.failed` with status `failed`                                                                                | Reservation becomes `failed_released`; provider bill projection and one POS outbox event are committed.                                                                                        |
| Cancelled                       | Signed `payment.failed` with session status `cancelled`                                                                     | Browser cancel return changes no money. Authoritative provider cancellation releases reservation and emits the canonical failed-family event.                                                  |
| Expired                         | Signed `payment.expired` with status `expired`                                                                              | Authoritative event releases reservation and emits `payment.expired`. Baseline scheduler did not complete this path.                                                                           |
| Browser abandonment             | No state change                                                                                                             | Provider webhook/reconciliation must finish the lifecycle. Baseline scheduler was insufficient after `expires_at`.                                                                             |
| Return after local expiry       | Return page rendered `expired` from local time even if stored state remained active                                         | This was UI-only on return, but contradicted financial authority and stopped polling prematurely.                                                                                              |
| Late authoritative success      | `failed`/`cancelled`/`expired` -> `paid` is permitted only through authoritative event processing                           | Released capacity is reacquired atomically; conflict fails closed if another method consumed it.                                                                                               |
| Cash or terminal partial/full   | POS reports a completed fact -> shared reserve -> private idempotent commit -> local projection                             | Smaller amount produces `partially_paid`; final amount produces `paid`. Same logical payment retry returns prior result.                                                                       |
| Sequential traditional payments | Each distinct completed fact reserves the remaining shared capacity                                                         | Total protected/completed cannot exceed bill total.                                                                                                                                            |
| Traditional + digital           | Both use the same capacity projection                                                                                       | Traditional payment may use only the unprotected remainder while one digital session is active.                                                                                                |
| Concurrent methods              | Bill/reservations serialize at the Phase 1 boundary                                                                         | Losers fail before an external financial side effect.                                                                                                                                          |
| Bill update during payment      | Bill mutation uses the protected financial floor                                                                            | Increases are allowed by existing version rules; reductions below completed/reserved/ambiguous capacity fail.                                                                                  |
| Bill/table close during payment | Phase 3 lifecycle checks protected reservations                                                                             | Close/cancel fails with `payment_in_progress`; financially paid does not itself close the table visit.                                                                                         |

## Baseline source-of-truth hierarchy

1. Signed provider event for terminal digital outcomes.
2. Private provider session read for reconciliation evidence, but baseline code did not commit terminal reads.
3. POS completed fact for traditional payments.
4. Restec locked financial reservation and canonical bill projection.
5. Browser redirects and local clocks are presentation signals only and must not be financial authority.
