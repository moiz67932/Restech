# Phase 4 authoritative digital state machine

| State                      | Terminal / customer action              | Reservation           | Allowed next states                                   | Authority / POS / reconciliation                                                                                                 |
| -------------------------- | --------------------------------------- | --------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `creating` (internal)      | No / no                                 | Reserved or ambiguous | action, processing, paid, failed, expired             | Private create/result or reconciliation. Creation ambiguity remains protected.                                                   |
| `requires_customer_action` | No / yes before local checkout deadline | Reserved              | processing, paid, failed, cancelled, expired          | Provider event/read. Local deadline only blocks a new redirect.                                                                  |
| `processing`               | No / no                                 | Reserved              | paid, failed, cancelled, expired                      | Provider event/read. Never released by age alone.                                                                                |
| `paid`                     | Yes / no                                | Completed             | Phase 5 refund states only                            | Signed completion or reconciled authoritative paid state plus verified bill projection. Emit one `payment.completed`. Monotonic. |
| `failed`                   | Yes / retry via a new session           | Released              | paid through late-success capacity reacquisition only | Signed/provider-confirmed failure. Emit one `payment.failed`.                                                                    |
| `cancelled`                | Yes / retry via a new session           | Released              | paid through late-success capacity reacquisition only | Signed/provider-confirmed cancellation. Browser cancel is not authority. Uses the failed-family POS event in v1.                 |
| `expired`                  | Yes / retry via a new session           | Released              | paid through late-success capacity reacquisition only | Signed/provider-confirmed expiry. Emit one `payment.expired`. Local time alone is insufficient.                                  |

Repeated identical transitions are no-ops. Different technical event IDs for the same session and logical terminal state reuse the same logical POS event. A forbidden transition is rejected. A late paid result that cannot reacquire capacity is a review-required conflict, never a silent overpayment.
