# Phase 4 normal-payment policy decisions

| Decision                                                       | Evidence / existing runtime                                                                                                                | Safe policy and impact                                                                                                                                                      | Status                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| One active digital session                                     | Phase 1 memory check, PostgreSQL partial unique index, tests, partner docs                                                                 | Keep one active/ambiguous digital reservation per bill. Traditional payments may use only other available capacity.                                                         | ALREADY_DEFINED                             |
| Multiple POS partials                                          | Shared reservation architecture and existing endpoint                                                                                      | Allow distinct completed facts until shared capacity is exhausted.                                                                                                          | ALREADY_DEFINED                             |
| Cash + digital; terminal + digital; cash + terminal; three-way | All supported methods use the same generic capacity boundary                                                                               | Allow any sequence against shared available capacity. No method-specific allocation.                                                                                        | ALREADY_DEFINED                             |
| Traditional intermediate states                                | Contract schema requires literal `completed`; docs reject other values                                                                     | POS/terminal owns pending, declined, cancelled, voided, and reversed states in v1.                                                                                          | ALREADY_DEFINED                             |
| Digital expiry authority                                       | `expires_at` exists, but repository contains no guarantee that the provider cannot later succeed; private GET exposes authoritative status | Local time only disables customer action. Release only after a signed `payment.expired` event or private provider read reporting terminal `expired`.                        | IMPLIED_BUT_AMBIGUOUS, RESOLVED FAIL-CLOSED |
| Cancellation authority                                         | Cancel return already records `provider_state_unchanged`                                                                                   | Only signed event or authoritative private provider state `cancelled` releases. Browser navigation never cancels money.                                                     | ALREADY_DEFINED                             |
| Failure authority                                              | Signed `payment.failed` path already releases                                                                                              | Signed event or authoritative private provider state `failed` releases. Local/network error remains protected.                                                              | ALREADY_DEFINED                             |
| Processing lifetime                                            | Active states are reconciled and reservations are protected                                                                                | No local timeout releases `processing`; continue reconciliation until provider terminal evidence.                                                                           | IMPLIED_BUT_AMBIGUOUS, RESOLVED FAIL-CLOSED |
| Bill close with active session                                 | Phase 3 rejects terminalization with protected capacity                                                                                    | Operator/POS must wait for authoritative terminal outcome; paid state does not itself close table lifecycle.                                                                | ALREADY_DEFINED                             |
| Late success                                                   | Phase 1 permits terminal released -> paid only with atomic capacity reacquisition                                                          | Commit if capacity is still available; otherwise retain conflict for manual reconciliation and never overpay.                                                               | ALREADY_DEFINED                             |
| Tip and pricing changes                                        | No post-session tip API; bill mutation has a protected floor                                                                               | Tip must already be part of bill total. Increases may follow version rules; reductions below protected floor fail.                                                          | ALREADY_DEFINED                             |
| Customer-requested cancellation                                | Return route explicitly does not change provider state                                                                                     | Treat as checkout exit only. A future provider cancellation API requires a separate approved contract.                                                                      | ALREADY_DEFINED                             |
| Automatic expiry                                               | Reconciliation route and production cron already exist                                                                                     | Scheduler queries provider after local due time. It terminalizes only provider-confirmed terminal state; otherwise retains reservation and records review/pending evidence. | ALREADY_DEFINED BY SAFE AUTHORITY RULE      |
| `other` traditional method                                     | Existing open-decision document restricts it to approved onboarding                                                                        | Keep contract-compatible but require onboarding approval; do not infer new categories.                                                                                      | ALREADY_DEFINED                             |

No financially safe implementation may claim that local `expires_at` alone proves expiry. Provider sandbox certification of the private GET semantics remains gated, so runtime fails closed by retaining capacity whenever the provider does not report a terminal state.
