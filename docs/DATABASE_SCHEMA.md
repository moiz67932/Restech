# Database Schema

Tenant and access tables are `partners`, `partner_users`, `restaurants`, `locations`, and `api_keys`. Connector state uses `pos_connections`, `pos_tables`, `table_mappings`, and encrypted `webhook_endpoints`. Financial mappings use `bill_mappings`, `external_payments`, and additive `payment_sessions`. Reliability uses `idempotency_records`, `replay_records`, `private_event_inbox`, `pos_outbox_events`, `webhook_delivery_attempts`, and sandbox-only `mock_pos_receipts`. `audit_logs` records controlled actions with sanitized metadata.

Unique constraints protect key prefixes, environment/location connections, external table mappings, external bills/payments, public payment-session IDs, active sessions per bill, request IDs, private event IDs, public event IDs, and logical delivery deduplication. Claim indexes support pending work, session expiry, and expiring leases. Financial, delivery, and audit relationships restrict deletion. RLS is enabled; browser roles cannot read integration or financial tables. `accept_payment_session_event` atomically updates the session/bill and inserts inbox/outbox evidence, while `claim_pos_outbox` uses `FOR UPDATE SKIP LOCKED`.

`payment_sessions` stores no customer contact or cardholder data. The hosted checkout URL is AES-256-GCM ciphertext under the existing secret-encryption key; only its exact hostname is separately stored for redirect validation. The pre-create/attach flow plus deterministic private idempotency makes a retry safe after a private commit/local attachment failure.
